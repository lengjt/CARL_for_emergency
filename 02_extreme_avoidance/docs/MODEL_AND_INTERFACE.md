# 模型、接口与判定约定

## 1. 模块与数据流

`configs/scenarios/*.json` → `Scenario` → `AvoidanceEnv.observe()` → `Baseline / RollingPlanner` → `[转角请求, 纵向力请求]` → 公共执行器与延迟 → OCD 原生模型 → 几何检查与恢复检查 → CSV / JSON / 曲线 / HTML。

| 文件 | 职责 |
|---|---|
| `native/bridge.cpp` | 为固定的一种 OCD 模型组合提供 pybind11 接口和独立 MF52 轮胎台架 |
| `backend.py` | 原生状态初始化、轮速初始化、延迟、纵向力执行器、简化滑移调节、逐轮路面查询 |
| `scenario.py` | 直线/圆弧道路、静态矩形障碍、时空附着分区、矩形 SAT 与道路余量 |
| `environment.py` | reset/step、障碍揭示、物理步级几何检查、独立事件/恢复指标 |
| `controllers.py` | 纯制动、转向避让、联合机动、巡航道路跟踪 |
| `prediction.py` | NumPy 批量非线性自行车 RK4 预测器，暂不参与实际闭环控制 |
| `planner.py` / `native/planning.hpp` | 在线格点候选搜索、独立 C++ 自行车预测器、扫掠检验、排名与回退 |
| `experiment.py` | 运行记录、来源哈希、曲线、离线浏览器回放 |

本地 `upstream/manifest.json` 是精选源码快照清单，不是完整递归 Git checkout；它记录各仓库提交、路径和 Git blob SHA。源码方程未修改，`native/` 是本项目的绑定。上游许可文件随源码保存，构建不下载依赖。

## 2. 坐标与车辆参数

采用 SI 单位：米、秒、弧度、牛顿。世界坐标右手系，x 向前、y 向左、yaw 逆时针为正；车体速度 vx/vy 与横摆角速度分别用 m/s、rad/s 表示。道路坐标 s 为弧长、d 为左侧横向偏移。

| 参数 | 当前冻结值 |
|---|---|
| 质量 / 横摆惯量 | 800 kg / 1000 kg·m² |
| 轴距 / 质心距前轴 | 3.2 m / 1.724 m |
| 前/后轮距 / 轮胎滚动半径 | 1.6 / 1.5 m；0.3 m |
| 质心高度 | 0.3 m |
| 碰撞车身 | 4.6 × 1.9 m 矩形，几何中心假设与质心重合 |
| 转向幅值 / 速率 / PT1 常数 | 0.3 rad / 0.5 rad/s / 0.06 s |
| 请求制动力 / 驱动力上限 | 10000 N / 4000 N |
| 前制动比例 | 0.6 |
| 公共命令延迟 | 0.04 s |
| 纵向力建立时间 / 变化率 | 0.08 s / 80000 N/s |
| 物理步长 / 控制周期 | 0.001 s / 0.02 s |

完整配置为 `configs/vehicle.json`。保留默认研究车的悬架、空气动力学与轮胎框架，同时显式记录用于左右对称实验的轮胎偏置参数调整。它是合成研究配置，不是现实乘用车辨识结果。所有控制器共用执行器、制动分配和延迟。

`FX` 输入是驱动系统的纵向力请求，由 OCD 映射为轮端力矩，不能等同于实际接地力。外部公共纵向执行器之后还经过简化制动滑移调节：以最严重制动滑移调节统一制动强度，没有四通道独立 ABS，也没有牵引力控制。实际轮胎力与请求力同时保存。

原生适配器读取积分后的位姿/速度；轮胎力、轮荷等诊断值来自 OCD 最后一个 RK 求值阶段，存在单步内时序差别。t=0 的诊断量为占位零值，物理统计与画图应忽略它们。在线实验版本通过本地 `ObservedSteering` 包装读取最终积分转角，修复旧接口把最后 RK 阶段转角当作最终状态的问题；上游动力学方程未改动。差分转向速率仍保留 0.001 rad/s 数值容差，并单独记录峰值。

## 3. 路面与障碍

道路采用横向条带，提供直线或定曲率圆弧。`road.length` 用于场景展示与无障碍路程完成判定，不是前后方向的实体墙；碰撞边界是道路左右边缘。当前几何不表示坡度、路肩或路面高程。

每个物理步查询四个轮位的 `scale_at(x,y,t)`。新实验 `friction_mode=internal_mu` 将 `base_scale` / `patches[].scale` 用于各轮 `LMUX/LMUY` 基准值的倍乘，外部 `lambda_mue=1`，记号为 `lambda_peak`。旧模式 `post_force` 在 MF52 输出后倍乘，记号为 `lambda_F`。无模式字段的旧场景默认使用旧模式。分区用 s/d/t 区间覆盖，重叠时最后一个匹配分区生效。完整定义见 `configs/friction_definition.json` 和 `docs/FRICTION_DEFINITION.md`。

轮胎台架实测：Fz=2500 N 时，scale=1 的采样峰值 |Fx|/Fz≈1.461、|Fy|/Fz≈1.179；scale=0.5 时分别≈0.731、0.589。这说明“scale=0.5”不表示“μ=0.5”。完整采样范围、轮荷依赖与曲线见物理实验目录的 `tire_calibration.json`；这只是冻结轮胎模型的有限网格计算。

障碍自 t=0 起物理存在，但当 `obstacle.s - ego.s <= reveal_distance` 才向控制器揭示；揭示后不会再次隐藏。碰撞检查始终包含所有障碍。因此“突现”是感知信息揭示，不是突然生成实体。当前不提供图像、遮挡推理或感知噪声。

`capability_scale_estimate` 是带可选倍率偏差/时间延迟的真值代理，不是实际附着估计器；`force_scale_estimate`、`scale_estimate` 为兼容别名。rolling 使用当前最小轮端估计值，三个旧避障基线没有使用该估计值。新观察还含当前纵向执行器状态、已施加命令和延迟队列，使候选预测从相同的控制历史开始。

## 4. 安全、避障与恢复

每个物理步用车身矩形做检查。在相邻位姿之间以中点位姿加膨胀矩形形成保守扫掠包络；该保证依赖单步内线性位姿插值假设，不构成连续真实车辆运动的严格证明。SAT 的最大分离轴间隙用于碰撞判断，`min_sat_gap_m` 不是欧氏最短距离。道路检查考虑圆弧条带与矩形边缘。

指标分开定义：

- `passed_obstacles_at_s`：车身已越过全部障碍，按 s 方向半车长＋半障碍长再加 5 m 余量判断，且当步未碰撞/越界；事件时间锁存。
- `safe_stop_at_s`：所有障碍已揭示、车速模长 <0.1 m/s，且当步未碰撞/越界；事件时间锁存。它本身不表示已经稳定保持。
- `avoidance_success`：曾达到以上任一事件。它只描述障碍处理事件，后续失稳并不会撤销该历史事件；无障碍场景为 null。
- `stable_recovery`：在无碰撞、无越界条件下持续达到恢复阈值，终止状态为 `recovered` 或 `stopped_safe`。`success` 进一步要求无执行器约束违反。
- `recovery_failed`：曾完成障碍处理，但最终因为越界、碰撞、超时或数值异常而未稳定恢复。

恢复阈值在场景文件中冻结：|航向误差|<0.05 rad、|侧偏角|<0.05 rad、|横摆角速度−道路曲率×vx|<0.08 rad/s，持续 0.8 s。绕行后还要求 |d|<0.35 m；安全停车允许停在道路内的非中心位置，但仍要求上述姿态阈值。车速不被强制置零，约 0.03 m/s 的停车残余爬行保留在轨迹中。

终止状态为 `collision`、`offroad`、`timeout`、`numerical_failure`、`stopped_safe`、`recovered`。异常结果不得标为物理不可行。多个障碍的几何检查已实现，但基础避让控制器仅围绕首次揭示的最近障碍构造机动；本次避障实验均为单障碍。

## 5. 控制基线与数据接口

`aeb`：障碍揭示后最大制动，仍做道路中心跟踪。`steer`：五次平滑横向偏移参考＋反馈跟踪，揭示后滑行。`joint`：同类转向参考＋固定制动力，恢复门控要求回归车道和姿态稳定后才允许正驱动力，且限为 1000 N。`cruise`：无障碍道路跟踪。

这些是工程对照基线，没有最优性保证。旧 `joint` 过早恢复驱动力的实现保留为 `joint_legacy`，用于恢复失败对照。`sample` 仍是离线模板枚举；新 `rolling` 是独立的在线滚动格点采样规划器，详情见 `docs/ONLINE_PLANNING.md`。

```python
from extreme_avoidance.scenario import Scenario
from extreme_avoidance.environment import AvoidanceEnv

env = AvoidanceEnv(Scenario.load("straight_critical"))
observation = env.reset()
# 用将来的规划器替换下面的动作；单位是 rad 和 N。
observation, done, metrics = env.step((0.02, -2500.0))
```

这不是 Gymnasium API：step 返回三个值，没有 reward。`observation` 包含结构化车身/轮胎状态、道路坐标、已揭示障碍和附着缩放代理。环境结束后必须 reset，reset 会重建原生模型并清空延迟队列与历史事件。

`prediction.rollout(initial, actions)` 输入形状为 `(batch, steps, 2)`，输出 `(batch, steps+1, 8)`，状态为 `[x,y,yaw,vx,vy,yaw_rate,steering,force]`。该近似模型用有效纵/横摩擦系数而非 `lambda_mue`，省略轮速、悬架和 ABS，没有自动微分链。目前仅验证批次一致性，尚未验证它对 OCD 的预测误差，不应用它直接生成“高可信专家”标签。

未来 Transformer＋CFM 可先输出反馈机动参数或低维控制序列，在同一延迟/执行器约束下交给 OCD 复核。数据集按独立场景分组划分，不能把同场景左右分支随机拆进训练集和测试集。当前 seed 仅为记录字段，所有场景与控制器都是确定性的，没有随机采样过程。

## 6. 可追溯性与尚待完成的研究工作

每次实验保存完整场景/车辆配置、初始化参数、控制器参数、Python/NumPy/平台版本、上游提交、本地实现与原生模块 SHA256，以及各输出文件的 SHA256 清单。CSV 为控制周期采样；碰撞、越界与恢复检查在每个物理步执行。控制器计时涵盖观察组装与控制调用，不包含仿真步进、绘图或构建；这不是未来生成规划器的端到端时延。

后续工作包括目标乘用车参数辨识、CarSim/实测对照、低速模型改进、独立轮端牵引力/稳定性控制、长时域预测误差处理、更强连续采样/优化基线以及生成模型训练。在线滚动格点基线和直路有限实验矩阵已实现，结论仍仅限于合成研究车辆。
